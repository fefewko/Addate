1. Реализовано

1.1. Аудит безопасности (13.11.2026)

Миграции применяются вручную через Supabase SQL Editor. Все шаги идемпотентны и выполнены отдельными транзакциями.

1.2. E2EE-переписка

  • Защищённое хранение приватного ключа и KEK (secureStorage.ts), миграция старых значений.
  • Резервная копия ключа, восстановление на новом устройстве, синхронизация при смене пароля.
  • Идемпотентная отправка: client_message_id + уникальный индекс, обработка 23505, защита от двойного тапа.
  • Защита от replay: запоминание nonce переписки.
  • TOFU + отпечаток ключа, баннер и блокировка отправки при смене ключа собеседника.
  • Удаление «у себя» (message_deletions) и «у обоих» (RPC delete_message(), только автор, очистка content/image_path).
  • Realtime на UPDATE/DELETE, long-press меню в Chat.tsx и QuickChatModal.
  • Push без текста: канал default, lockscreenVisibility = PRIVATE.
  • Предупреждения при неудачном восстановлении и при Telegram-входе без копии (SignIn.tsx).

1.3. Прочее

  • Обычный пользователь больше не меняет имя и дату рождения; чувствительные поля скрыты по умолчанию; раздел «Моя приватность» (включая веб-маршрут).
  • Исправлен перенос текста в пузырях по 1–2 буквы (0.0.38).
  • Собраны и проверены APK 0.0.36, 0.0.37, 0.0.38; expo-secure-store подтверждён в dex; tsc без ошибок.
  • Обновлены отчёты аудита, статусы миграций и версии.

2. Текущее

Активной разработки нет — код и миграции в согласованном состоянии, рабочее дерево чистое, последний коммит 1febb8b5.

Осталось только то, что нельзя выполнить в репозитории:

  1. Установить APK 0.0.38 (android/app/build/outputs/apk/release/app-release.apk) и прогнать сценарии на устройстве:
    • перенос текста в пузырях;
    • вход по паролю и расшифровка старой истории;
    • двойной тап по «Отправить» → одно сообщение;
    • long-press → удаление у себя / у обоих;
    • кнопка «Ключ» с отпечатком и баннер при смене ключа;
    • push: в шторке только имя и «Новое сообщение», на локскрине содержимое скрыто.
  2. Проверка push заблокирована отсутствием Android-устройства с реальными уведомлениями.

3. Будущее

3.1. Высокий приоритет (данные и доступ)

  1. C3 — взаимность лайков. status = 'matched' всё ещё ставит клиент. Нужен RPC, который проверяет встречный лайк; иначе можно открыть переписку с незнакомым.
  2. C5 — приватный бакет avatars. При show_photos = false скрывается только ссылка, файл доступен по прямой. Нужны приватный бакет, signed URL и миграция сохранённых ссылок.
  3. C8 — решение по модерации. Либо автоодобрение после заполнения анкеты, либо явная очередь для модератора.
  4. Админ-контур: MFA администратору, audit log действий модерации, подтверждение email и усиление парольной политики.

3.2. E2EE

  1. Double Ratchet / X3DH — forward secrecy и пост-компрометационная стойкость.
  2. Кодовая фраза восстановления для аккаунтов без пароля (Telegram).
  3. Нативный KDF (Argon2id) вместо PBKDF2; минимум — поднять итерации до ≥ 210 000 с ленивой миграцией.
  4. Сверка ключей через QR или общий код, а не только TOFU.
  5. Удаление превью последнего сообщения из matches при «удалить у себя».
  6. Очистка старых расшифрованных фото из documentDirectory у пользователей ≤ 0.0.35.
  7. Перевод панели модерации с localStorage на сессионное хранение ключа.

3.3. Инфраструктура и релиз

  1. C13 — бэкапы БД: документировать процесс и провести проверку restore.
  2. C14 — Edge-функции: вернуть в репозиторий исходники telegram-start, telegram-exchange, delete-account; отдельно проверить, что delete-account требует JWT и удаляет только auth.uid().
  3. Google Play Data Safety: актуализировать черновик перед Android-релизом (после переноса production в РФ).
  4. Настроить линтер: npx expo lint не настроен, автоподстановка eslint ломает репозиторий.

3.4. Задокументированные ограничения (не баги)

  • «Удалить у обоих» не отзывает уже полученное: скриншоты, сохранённые фото, прочитанный текст.
  • Компрометация долгосрочного ключа раскрывает всю переписку, зашифрованную на этот ключ.
  • Подмена ключа до первого контакта не обнаруживается (TOFU).
  • Копии ключа в старых резервных копиях ОС, сделанных до 0.0.36.
