# Как собрать проект из этих файлов

## Что нового в этой версии

- **Блокировка теперь работает по-настоящему**: раньше запись о блокировке создавалась, но диалог с этим человеком всё равно оставался в "Сообщениях", и писать друг другу технически было можно. Теперь: список диалогов исключает заблокированных, а на уровне базы данных отправка сообщений между заблокированными парами запрещена в принципе (даже если кто-то обойдёт интерфейс приложения).


## Что нового в этой версии

- **Список диалогов обновляется сам**: раньше "Общение" подгружался только при заходе на экран — если сидеть на нём и получить сообщение, точка непрочитанного не появлялась, пока не выйти и не вернуться. Теперь список обновляется сразу через realtime.


### Как это работает под капотом
При новом сообщении Postgres-триггер сам дёргает Edge Function `send-message-push`, которая находит получателя и отправляет ему push через Expo Push API. Токен устройства сохраняется в новую таблицу `push_tokens` при каждом входе в приложение.

### Нужно сделать вручную
1. Установить зависимости: `npx expo install expo-notifications expo-device`
2. В Supabase Dashboard → Edge Functions → Secrets добавить `PUSH_NOTIFY_SECRET` со значением:
   `a3f7e9d2c1b84f6a9e0d5c7b3a2f1e8d6c4b9a0f2e7d1c5b8a3f6e9d0c2b7a4f`
   (это тот же секрет, что уже зашит в триггер на стороне базы — просто продублировать его тут, чтобы функция могла проверить, что запрос пришёл от нашего триггера, а не откуда-то ещё)
3. **Push-уведомления не работают в Expo Go и не работают в эмуляторе** — проверять нужно на реальном телефоне, установив собранный `.apk`.

- **Кнопка "Написать сообщение" в полной анкете**: если с человеком уже подтверждённое совпадение, вместо кнопки лайка показывается кнопка сообщения, ведущая в чат. Заодно исправлен тот же баг с двусторонним определением совпадения, что чинили в других местах.
- **Компактный значок статуса вместо большой плашки** на карточках вкладки "Все": маленький кружок в углу фото — крестик (не лайкнуто, тап отправляет лайк), одна галочка (лайк отправлен, ждём ответа), две галочки (совпадение, тап открывает быстрый чат).



## Что нового в этой версии

- **Статус "в сети"**: приложение обновляет метку активности каждые 45 секунд, пока открыто. "В сети" — если был активен последние 3 минуты. Видно в карточках ленты, списке "Все" и на полной анкете.
- **Полный просмотр анкеты**: тап по карточке в ленте или в "Все" открывает отдельный экран со всеми фото, ростом/весом, статусом, употреблением и текстом "о себе".
- **Значок непрочитанных** на вкладке "Сообщения" (число) и точка рядом с конкретным диалогом в списке совпадений. Сообщения отмечаются прочитанными автоматически при открытии чата.
- **Возраст в сообщениях**: теперь показывается рядом с именем и в списке диалогов, и в заголовке самого чата.

В базе добавлено поле `last_seen_at` и политика RLS на обновление `read_at` у сообщений — уже применено на твоём Supabase-проекте.

## Что нового в этой версии

- Иконка приложения: положи свой `logo.png` в папку `assets/` (создай, если её нет) — `app.json` уже настроен на этот файл.
- Новый экран **Профиль** (вкладка внизу): город, рост, вес, статус трезвости, употребление, доп. фото (до 4 шт.), кнопки "Выйти" и "Удалить анкету". Email показывается, но не редактируется.
- Новая вкладка **Все** — список всех одобренных анкет без ограничений ленты (лайкнутые не пропадают из списка, а помечаются "Отправлено").
- В базе данных добавлены поля `height_cm`, `weight_kg`, `additional_photos` — уже применены на твоём Supabase-проекте, ничего вручную делать не нужно.
- Исправлен баг: незаконченная анкета (без имени) теперь ведёт на `ProfileSetup`, а не на экран модерации.

**Важно про "Удалить анкету":** кнопка удаляет запись из таблицы `profiles` (и всё, что на неё ссылается — совпадения, сообщения, жалобы). Сам аккаунт в Supabase Auth при этом не удаляется — это требует serverside-функции с правами администратора, которую можно добавить отдельно, если понадобится настоящее "удаление аккаунта" с возможностью повторной регистрации на тот же email.


## Что изменилось в этой версии

**Важно:** после замены файлов нужно заново собрать `.apk` — эти изменения не появятся в уже установленном приложении сами.


## 1. Создай каркас Expo-проекта

В PowerShell:

```
cd C:\ADDate
npx create-expo-app@latest . --template default@sdk-57
```

Если появится ошибка про непустую папку — значит в ней уже есть `.git`, `README.md` и т.п. из GitHub. Это нормально, попробуй ещё раз с флагом:

```
npx create-expo-app@latest . --template default@sdk-57 --yes
```

Если и это не поможет — создай во временной папке и перенеси файлы:

```
cd C:\
npx create-expo-app@latest ADDate-temp --template default@sdk-57
robocopy C:\ADDate-temp C:\ADDate /E
rmdir /S /Q C:\ADDate-temp
```

## 2. Замени файлы на файлы из этого архива

Распакуй этот zip и скопируй его содержимое **поверх** только что созданного проекта в `C:\ADDate`, подтвердив замену `App.tsx`.

## 3. Установи дополнительные зависимости

Из папки `C:\ADDate`:

```
npx expo install @supabase/supabase-js react-native-url-polyfill @react-native-async-storage/async-storage @react-navigation/native @react-navigation/native-stack @react-navigation/bottom-tabs react-native-screens react-native-safe-area-context expo-image-picker
```

## 4. Проверь .env

Файл `.env` уже заполнен реальными данными твоего Supabase-проекта (URL и анонимный ключ) — ничего менять не нужно. Этот ключ безопасно коммитить в Git: доступ к данным всё равно ограничен политиками RLS, которые мы настроили в базе, а не секретностью ключа.

## 5. Запусти проект

```
npx expo start
```

Отсканируй QR-код приложением **Expo Go** на Android-телефоне — так можно проверить всё быстро, без сборки `.apk`.

## 6. Дальше — сборка

Когда проверишь, что всё работает через Expo Go, выполни `eas build:configure` — теперь он сработает, так как папка стала настоящим Expo-проектом. Затем запушь изменения на GitHub и подключи репозиторий в дашборде expo.dev (Settings → GitHub), как договаривались раньше.
