# Выкладка веб-версии на addate.ru/web

Веб-версия — тот же код приложения, что и в APK, собранный под браузер. Она
лежит по адресу `https://addate.ru/web/` и не заменяет главную страницу сайта
и страницы соглашений: они остаются в корне домена.

## Важно: почему нельзя задеплоить только папку

В сборке путь `/web` зашит в ссылки на ассеты (`experiments.baseUrl` в
`app.json`). Если задеплоить `web-build/web` как корень сайта, страница
запросит `project.pages.dev/_expo/...` и получит 404 — откроется белый экран.

Поэтому приложение обязано лежать в папке `web/` **внутри** того же сайта,
который отдаёт `addate.ru`. Отдельным Pages-проектом `/web` не выносится.

## Правила в `_redirects` и почему их пять

Cloudflare прямо предупреждает в документации:

> Redirects are always followed, regardless of whether or not an asset
> matches the incoming request.

То есть правило `/web/* → index.html` перехватывает **всё** внутри `/web`,
включая запросы к файлам. Если ограничиться одним правилом, запрос бандла
`/web/_expo/static/js/web/AppEntry-<hash>.js` вернёт `index.html`, браузер
попытается выполнить HTML как скрипт — и страница останется белой **без
единой ошибки в консоли**.

Поэтому правила идут в таком порядке, и порядок здесь часть решения:

```
/web  /web/  301
/web/_expo/*  /web/_expo/:splat  200
/web/assets/*  /web/assets/:splat  200
/web/favicon.ico  /web/favicon.ico  200
/web/*  /web/index.html  200
```

Первые две строки для ассетов переписывают путь в себя же, и Cloudflare
отдаёт настоящий файл. Последняя — SPA-маршрутизация для `/web/feed`,
`/web/chats` и подобных, нужна потому, что `web.output: "single"` собирает
единственный `index.html`.

## Что нужно сделать один раз

**1. Разрешить адрес подтверждения в Supabase.**

В `Supabase → Authentication → URL Configuration → Redirect URLs` добавьте:

```
https://addate.ru/web/auth/callback
```

Без этого Supabase не примет адрес и вернёт письмо со ссылкой на сайт по
умолчанию — подтвердить email в браузере будет нечем. Адрес собирается из
`origin` браузера (см. `src/lib/webLinks.ts`), поэтому в разработке подставится
`http://localhost:8081`, и его тоже полезно внести для локальных проверок.

**2. Убедиться, что addate.ru отдаётся из Cloudflare Pages.**

Если корневой домен обслуживается чем-то другим (VPS, nginx, другой хостинг),
то `_redirects` из этого проекта Cloudflare не применится, и `/web` вернёт
404. В этом случае нужен либо перенос всего сайта на Pages, либо Worker на
`addate.ru`, который отдаёт `/web/*` из Pages-проекта.

## Сборка и проверка

```bash
npm run build:web                              # собрать и проверить
npm run serve:web                              # посмотреть локально
npm run merge:web -- C:\путь\к\корню-сайта     # встроить в существующий сайт
npm run verify:site -- C:\путь\к\корню-сайта   # проверить перед выкладкой
```

`build:web` падает, если:

- `index.html` ссылается на файл, которого нет в сборке;
- в корне результата остался `index.html` (он перезаписал бы главную страницу);
- `experiments.baseUrl` в `app.json`, `WEB_BASE_PATH` в коде и папка сборки
  разошлись;
- в бандл не попал адрес Supabase (страница откроется и упадёт на запросах).

`merge:web` **дописывает** правила в существующие `_redirects` и `_headers`, а не
заменяет файлы: они управляют всем сайтом, и перезапись молча сломала бы
остальные страницы. Скрипт идемпотентен — повторный запуск ничего не дублирует.

`verify:site` повторяет порядок обработки Cloudflare (сначала правила, потом
файл) и проверяет, что каждый ассет приложения отдаётся с правильным типом
содержимого, а не как `text/html`. Локальный сервер для разработки такому
не подвержен: он отдаёт файлы первыми, поэтому белая страница видна только
на настоящем хостинге.

## Выкладка

После `merge:web` в корне сайта должно получиться так:

```
/                       <- корень Pages: ваша главная страница
  index.html
  ...страницы соглашений
  _redirects            <- дописан скриптом
  _headers              <- дописан скриптом
  web/
    index.html
    _expo/
    assets/
```

Дальше — обычная выкладка этого каталога в Cloudflare Pages: git-интеграция
(папка `web/` и файлы в том же репозитории) или `npx wrangler pages deploy
<путь-к-корню-сайта>`.

Проверить после выкладки:

```
https://addate.ru/               -> главная страница
https://addate.ru/web/           -> форма входа
https://addate.ru/web/favicon.ico -> должен отдаться как картинка, а не как HTML
```

## Что работает, а что нет

**Работает:** вход и регистрация с email и паролем, подтверждение адреса по
ссылке из письма, заполнение анкеты с загрузкой фото, лента, список анкет,
список всех, диалоги с текстом и фото, просмотр анкет, избранное, настройки,
блокировки, чат с поддержкой, удаление анкеты.

**Не работает и скрыто:**

- **Push-уведомления.** В браузере им нужны service worker, ключи VAPID и
  правка функции отправки — это отдельная работа. Раздел «Уведомления» в
  настройках на вебе не показывается, чтобы не предлагать тумблер, который
  ничего не делает. Сообщения приходят в реальном времени через Supabase
  realtime, пока вкладка открыта.
- **Вход через Telegram.** Схема `tg://` в браузере не открывается; для него
  нужен официальный Telegram Login Widget с доменом, прописанным боту.
- **Кнопка «глаз»** у фотографий и свайпы работают на нативе как раньше.

## Особенности, о которых стоит знать

**Ключи Supabase видны в коде страницы.** В бандле лежат `EXPO_PUBLIC_SUPABASE_URL`
и `EXPO_PUBLIC_SUPABASE_ANON_KEY`. Это конструкция Supabase, а не утечка: anon-ключ
предназначен для публичного использования, а доступ к данным ограничивают
политики RLS, которые мы уже настроили. Но это значит, что защита данных держится
на RLS, а не на секретности ключа.

**Сессия лежит в localStorage.** Стандартное поведение Supabase в браузере:
пока вкладка не закрыта, вход сохраняется. На чужом компьютере это стоит
учитывать — выход из аккаунта стирает сессию.

**Одно предупреждение в консоли.** `expo-notifications` печатает
`Listening to push token changes is not yet fully supported on web` — это
побочный эффект `import` внутри самой библиотеки, а не ошибка приложения.
Убрать его можно только полным отказом от импорта на вебе, то есть отдельной
версией `pushNotifications` для браузера. Пока предупреждение безвредно и
оставлено: одна строка в консоли честнее, чем молчаливая подмена модулей.
