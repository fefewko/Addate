# Выкладка веб-версии на addate.ru/web

Веб-версия — тот же код приложения, что и в APK, собранный под браузер. Она
лежит по адресу `https://addate.ru/web/` и не заменяет главную страницу сайта
и страницы соглашений: они остаются в корне домена.

## Что нужно сделать один раз

**1. Разрешить адрес подтверждения в Supabase.**

В `Supabase → Authentication → URL Configuration → Redirect URLs` добавьте:

```
https://addate.ru/web/auth/callback
```

Без этого Supabase не примет адрес и вернёт письмо со ссылкой на сайт по
умолчанию — подтвердить email в браузере будет нечем. Адрес собирается из
`origin` браузера (см. `src/lib/webLinks.ts`), поэтому в разработке подставится
`http://localhost:8081`, и его тоже полезно внести для локальных проверок.

**2. Решить, где живут статические файлы.**

Сборка кладёт приложение в `web-build/web/`, а `_redirects` и `_headers` — в
корень `web-build/`. Cloudflare Pages читает `_redirects` и `_headers` только
из корня проекта, поэтому их нужно положить рядом с главной страницей, а не
внутрь `web/`.

## Сборка

```bash
npm run build:web
```

Скрипт собирает приложение, переносит его в `web/`, копирует `_redirects` и
`_headers` в корень и **проверяет результат**. Сборка падает, если:

- `index.html` ссылается на файл, которого нет в сборке;
- в корне результата остался `index.html` (он перезаписал бы главную страницу);
- `experiments.baseUrl` в `app.json`, `WEB_BASE_PATH` в коде и папка сборки
  разошлись;
- в бандл не попал адрес Supabase (страница откроется и упадёт на запросах).

Проверить локально, не выкладывая:

```bash
npm run serve:web
# http://127.0.0.1:8081/web/
```

Сервер повторяет поведение хостинга: монтирует сборку под `/web` и отдаёт
`index.html` на любой маршрут внутри него, иначе переход на `/web/feed` или
`/web/profile/<id>` дал бы 404.

## Выкладка

Скопируйте содержимое `web-build/` в корень проекта Cloudflare Pages:

```
/                       <- корень Pages: ваша главная страница
  index.html
  ...страницы соглашений
  web/
    index.html
    _expo/
    assets/
  _redirects            <- из web-build, положить в корень
  _headers              <- из web-build, положить в корень
```

Если `_redirects` и `_headers` у вас уже есть, допишите в них строки из
`web-build/`, а не заменяйте файлы целиком: они управляют всем сайтом.

В `_redirects` одна строка:

```
/web/*  /web/index.html  200
```

Она нужна для прямых переходов и обновления страницы на `/web/feed`,
`/web/chats` и подобных: без неё такие адреса отдают 404, потому что
`web.output: "single"` собирает одно `index.html`.

В `_headers` запрет кэша для `/web/*`: имя бандла содержит хеш, а у
`index.html` его нет, и без этого браузер продолжил бы открывать прошлую
сборку после обновления.

## Что работает, а что нет

**Работает:** вход и регистрация с email и паролем, подтверждение адреса по
ссылке из письма, заполнение анкеты с загрузкой фото, лента, список анкет,
список всех, диалоги с текстом и фото, просмотр анкет, избранное, настройки,
блокировки, чат с поддержкой, удаление анкеты.

**Не работает и скрыто:**

- **Push-уведомления.** В браузере им нужны service worker, ключи VAPID и
  правка функции отправки — это отдельная работа. Раздел «Уведомления» в
  настройках на вебе не показывается, чтобы не предлагать тумблер, который
  ничего не делает. Сообщения приходят в реальном времени через Supabase
  realtime, пока вкладка открыта.
- **Вход через Telegram.** Схема `tg://` в браузере не открывается; для него
  нужен официальный Telegram Login Widget с доменом, прописанным боту.
- **Кнопка «глаз»** у фотографий и свайпы работают на нативе как раньше.

## Особенности, о которых стоит знать

**Ключи Supabase видны в коде страницы.** В бандле лежат `EXPO_PUBLIC_SUPABASE_URL`
и `EXPO_PUBLIC_SUPABASE_ANON_KEY`. Это конструкция Supabase, а не утечка: anon-ключ
предназначен для публичного использования, а доступ к данным ограничивают
политики RLS, которые мы уже настроили. Но это значит, что защита данных держится
на RLS, а не на секретности ключа.

**Сессия лежит в localStorage.** Стандартное поведение Supabase в браузере:
пока вкладка не закрыта, вход сохраняется. На чужом компьютере это стоит
учитывать — выход из аккаунта стирает сессию.

**Одно предупреждение в консоли.** `expo-notifications` печатает
`Listening to push token changes is not yet fully supported on web` — это
побочный эффект `import` внутри самой библиотеки, а не ошибка приложения.
Убрать его можно только полным отказом от импорта на вебе, то есть отдельной
версией `pushNotifications` для браузера. Пока предупреждение безвредно и
оставлено: одна строка в консоли честнее, чем молчаливая подмена модулей.
