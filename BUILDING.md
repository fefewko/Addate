# Сборка APK локально

Сборка идёт на вашем ноутбуке, без облака EAS. Нужен Android SDK и JDK 17.

## Один раз: настройка окружения

1. **Android SDK.** Проверить:
   ```
   npx expo prebuild --platform android
   ```
   SDK ставится через Android Studio (SDK Manager) либо отдельно
   [command line tools](https://developer.android.com/tools).
   Если SDK не в стандартном месте, задайте переменную:
   ```
   setx ANDROID_HOME "C:\путь\к\Sdk"
   ```
   и перезапустите терминал.

2. **JDK 17.** Проверить: `java -version`

3. **Зависимости проекта:** `npm install`

4. **`.env`** — файл обязателен. Без него в бандл попадёт `undefined` вместо
   адреса Supabase, и приложение упадёт на старте. Файл в `.gitignore`, поэтому
   в облако не уезжает, а для локальной сборки как раз используется:
   ```
   EXPO_PUBLIC_SUPABASE_URL=https://<проект>.supabase.co
   EXPO_PUBLIC_SUPABASE_ANON_KEY=<anon-ключ>
   ```

## Сборка

```
npm run build:apk
```

Готовый файл:
```
android\app\build\outputs\apk\release\app-release.apk
```

Первый запуск занимает 5–10 минут (качаются Gradle и зависимости), последующие
около минуты, если менялся только JS.

## Когда нужен `--rebuild`

Папка `android/` генерируется из `app.json` и нативных зависимостей и **не**
пересоздаётся сама. Если вы поменяли нативный пакет или плагин, старая
нативная база устареет и правки в JS это не исправят:

```
npm run build:apk -- --rebuild
```

Обычные правки `.tsx` пересоздания не требуют.

## Ключи запуска

| Ключ | Назначение |
|---|---|
| `--arch x86_64` | для эмулятора на компьютере |
| `--arch all` | универсальный APK для всех архитектур (долго, нужно много памяти) |
| `--heap 6g` | поднять лимит памяти Gradle, если сборка обрывается |
| `--rebuild` | перегенерировать `android/` |

По умолчанию собирается только `arm64-v8a` — этого достаточно для любого
современного телефона. Четыре архитектуры сразу требуют заметно больше памяти:
на ноутбуке процесс обрывается на середине без внятного сообщения об ошибке.

## Ограничения этой сборки

**Подпись — отладочным ключом** `android/app/debug.keystore`. Сборка из
облачного EAS подписана другим ключом, поэтому APK из разных источников не
обновляют друг друга: перед установкой надо удалить прежнюю версию с телефона.
Постоянный ключ можно задать в `android/app/build.gradle` в
`signingConfigs.release`.

**Push-уведомления не работают.** Нужны FCM-credentials
(`google-services.json`), которых в проекте нет. Получить: Firebase Console →
проект → Cloud Messaging → Web/Android → файл `google-services.json` положить
в корень проекта и добавить в `.gitignore`.

**Это debug-сборка с dev-client.** Для публикации в Play нужен отдельный
релизный ключ и `expo prebuild --clean`.

## Проверка, что сборка не пустая

```
npm run verify:apk
```

Скрипт достаёт `assets/index.android.bundle` из APK и ищет в нём ключи
Supabase и маршруты приложения. Проверять нужно потому, что `.env` лежит в
`.gitignore` и в сборку не попадает: если переменные окружения не подставились,
`process.env.EXPO_PUBLIC_SUPABASE_URL` превращается в `undefined`, бандл
собирается **без единой ошибки**, а приложение падает на старте. По логам в
телефоне это ищется плохо, а вот эта проверка ловит сразу.

```
✓ реф Supabase-проекта
✓ фрагмент anon-ключа
✓ схема addate://
✓ маршрут auth/callback
✓ экран AuthCallback
✓ функция feed_profiles
✓ функция my_location
```

Путь к APK можно передать аргументом:
`npm run verify:apk -- D:\Downloads\addate.apk`
